# AI 产品开发全流程

把产品目标落实为可运行、可恢复、可验收的产品。产品经理说明用户、任务与成功标准；AI 负责技术方案、实现、验证和交接。以当前请求为范围，按可验证业务闭环推进，不要求用户学习框架或云平台术语。

## 先判断入口

读取已提供的 PRD、项目规则、阶段文档、接口与设计资料，检查代码、依赖、启动方式、Git 未提交修改与相关测试。不要求用户重新提供已有资料，不先重构再理解。只读取当前工作需要的参考：

| 当前任务 | 读取内容 | 预期结果 |
| --- | --- | --- |
| 新项目、需求变更、核心 Agent 开发 | [技术适配与核心开发](references/core-development.md) | 适配声明、阶段计划、真实核心链路 |
| 正式前端、交互纵向切片 | [前端与 Agent 交互](references/frontend.md)；语音产品再读[语音与媒体](references/voice-media.md) | 代表页、任务恢复、真实前后端闭环 |
| 首次上线、线上更新、部署排错 | [部署与运行](references/deployment.md) | 上线方案、可追溯发布、线上验收与回退 |
| 阶段验证、质量复核、交接 | [验收与交接](references/verification.md) | 带证据的结果、未验证项与下一步 |
| 维护本技能、核对转化依据 | [来源与裁决记录](references/source-decisions.md) | 区分手册经验、修正与待核验信息 |

已有项目从当前阶段进入；单点任务只应用相关约束，不补写整套文档。非 Web、纯端侧、硬件、游戏或严格实时产品保留状态与验收原则，重新适配终端，不机械套用 Web 架构。

## 统一决策规则

1. 用户当前要求与已有授权决定任务范围。业务以已确认 PRD、设计和验收标准为依据，技术以真实接口、合理现有架构与环境为依据，手册默认项最后适用。矛盾要说明影响并给一个推荐结论。
2. 区分三层：**工程底线**（密钥边界、权限、数据恢复、输入输出校验、真实验收）；**默认方案**（新项目 Python/FastAPI、Web Next.js）；**按需模块**（数据库、RAG、OCR、队列、语音等）。不要把示例版本、目录、环境变量、云平台或状态枚举变成通用硬规定。
3. 常规适配报告后继续；只对尚未授权且会显著改变产品目标、费用、外部数据传输、迁移或发布范围的决定询问。已有授权不重复确认；本人身份验证等必要操作给具体步骤，并继续其他可完成工作。
4. 给一个推荐技术结论及理由，不把框架选型交给产品经理。关键业务规则未冻结时，以标注清楚、可配置的临时规则推进，不冒充已验收结果。
5. 具体版本、模型、价格、地域、账号资格和 CLI 参数在实际采用时核对当前官方资料与本地工具，记录实际采用值。无法核实时标记待验证，不凭历史手册推断现状。

## 推进流程

### 1. 对齐范围与适配

确认七类信息：目标用户与任务；输入/过程/产物；交互和确认点；Agent 效果标准；本阶段优先级；模型与成本；数据及性能/终端/部署限制。技术缺项自行推导；缺 PRD 时形成可核对的最小产品摘要，不虚构业务指标。

检查实际解释器、版本、端口、依赖服务及密钥是否已配置，不打印秘密。新项目输出简短技术适配声明，已有项目维护原文档；模板见 [assets/technical-adaptation.md](assets/technical-adaptation.md)。

选择开发路径：一次提交、后台生成、下载结果默认**后端先行**；多轮对话、人工确认、画布或时间轴决定产品能力时选择**纵向切片**，尽早验证最小真实交互。默认先做一个主要终端。

### 2. 按业务闭环实现

使用 [assets/stage-plan.md](assets/stage-plan.md) 生成或补齐本阶段文档，包含契约、状态、恢复及可操作验收步骤；按任务规模裁剪，不重复另建文档体系。

按“最小用户任务 → 实现 → 运行 → 验证 → 修复”循环推进。核心能力待验证时不大规模铺开正式视觉；需要看长文、图像或人工确认才能判断质量时提供最小验收界面，已有交互切片继续复用。

用户授权整个产品时，在阶段证据通过后持续推进下一阶段；只授权某阶段时按该阶段交付。不要把分阶段解释成每阶段必须等待口头确认，也不要跳过必要的用户质量判断。

### 3. 验证与交接

按 [验收与交接](references/verification.md) 执行与变化相关的检查。模型核心链路需要 mock 自动化和真实模型冒烟两类证据；前端需要真实浏览器与真实后端闭环；上线需核对实际新版本、登录隔离、持久化、文件和核心链路。

无 Key 可继续开发与 mock 测试，真实模型验收保持待验证。没有浏览器、真机或云权限时如实报告限制，不用构建或模拟结果代替。

用 [assets/acceptance-handoff.md](assets/acceptance-handoff.md) 记录已通过、失败、待验证、不适用及证据。更新项目启动/配置/运行文档。告诉产品经理当前能做什么、打开哪里、如何验收、下一步是什么。

## 贯穿全程的实现边界

- 后端掌握业务事实、权限和秘密；前端通过受控接口访问。持久化任务、资产归属与关键确认点，刷新和重启后可继续。
- 模型输出先确定性解析再按契约校验；初始化、网络、限流、格式错误有有限重试与统一错误。外部写入、费用或不可逆动作由代码约束工具权限、预算、幂等和确认点，不能仅靠 Prompt。
- 密钥不进入前端、仓库、构建包、日志和聊天输出。录入使用后端安全入口或本地/平台 Secret；配置说明仅列键名和占位值。
- 保留用户改动、数据和已验证接口。重要删除、破坏性迁移与外部发布遵循会话授权边界；准备工作不因尚待最终决定而停滞。
- 测试、浏览器、模型与线上结论分别提供证据。不删除测试、隐藏错误、降低标准或伪造用户验收来声称完成。
