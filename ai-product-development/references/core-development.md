# 技术适配与核心开发

## 技术选择

新建 API 驱动的 AI MVP 默认 Python、FastAPI、Pydantic、pytest、Git；模型用官方 SDK 或实测兼容接口。原手册 Python 3.11、Node 22 是历史基线，实际选仍受维护且兼容项目与部署运行时的版本，锁定依赖。已有合理项目延续架构、目录与包管理器。

| 需求触发 | 推荐起点 | 升级或边界 |
| --- | --- | --- |
| 单用户、文件为主、简单索引 | 带 schema 版本的结构化清单 | 原子写入、损坏处理、并发限制；多用户/事务时重评 |
| 实体关系、事务、复杂查询、并发修改 | SQLite + SQLAlchemy + Alembic 用于合适的本地 MVP | 生产按并发与可靠性评估 PostgreSQL 或既有平台 |
| 语义检索且全文搜索不够 | 持久向量检索，如 Chroma | 记录切片/Embedding/索引版本；召回不等于回答正确 |
| Word / 文本 PDF | python-docx / pypdf | 默认 .docx；扫描件只有明确需要才加 OCR |
| 长任务 | 持久任务记录和状态查询 | 依据并发、时长、调度可靠性再引入队列 |
| 图片/音视频/大文档 | 文件或对象存储，结构化存储留元数据 | 记录归属、类型、路径/对象键、状态和清理规则 |
| 渐进输出 | SSE/Fetch Streaming | 只关心最终结果可提交后轮询；双向实时另行适配 |
| 动态选工具与规划 | 有界 Agent 执行器 | 固定流程优先代码状态机，不预装编排框架 |

API、校验结构、服务、Prompt、配置和测试分离；数据库/迁移/向量目录按需创建。新 API 可默认 `/api/v1`，已有前缀保持兼容；不兼容变化说明调用方和迁移路径。

## 状态与持久化

先定义当前阶段实际状态、合法转换及责任方，不预测全部未来状态。长任务至少记录 ID、所有者（存在用户时）、输入引用、状态、当前步骤、中间产物、错误类别、时间和幂等标识。保存实际模型/Prompt/规则版本。确认记录与任务及当前步骤绑定，防止确认过期结果。

明确进程退出、重启、任务中断后的识别与恢复：哪些步骤能重试，哪些先查外部结果，如何避免重复扣费。仅把 running 写入数据库却无恢复执行或终止判定，不算可恢复。

结构化文件必须有 schema 版本、原子替换、并发边界、损坏恢复和迁移路径。数据库变更考虑旧数据与回退；不能假定换 DATABASE_URL 就完成跨数据库迁移。

## 接口与流式契约

每个接口定义方法/路径、身份与归属校验、请求/响应 schema、错误码、超时、幂等与重试。普通错误可统一为 `{"error":{"code":"...","message":"..."}}` 并带请求 ID，内部与供应商异常在服务边界归一化。

SSE 基础契约为零到多条 `chunk`，成功以 `done`（完整结果或受控结果引用）结束，失败以 `error` 结束。进度、产物、音频事件另定 schema。HTTP 响应开始前可返回正确 HTTP 错误；流建立后由最外层兜底将 SDK 构造等异常也转为 `error`。

覆盖分片边界、多字节字符、终止事件和去重。网络断开可能无法送达终止事件，客户端按任务 ID 恢复；不能把无 done 或断流当成最终失败/成功。任务存活不依赖浏览器连接持续存在。

## 模型与 Agent

- 模型名、base URL、超时和参数来自配置；Prompt 独立管理且可版本追踪。模型/耗时/用量/错误只记必要元信息；费用未知就写估算或未获取。
- 区分认证、传输、限流、解析与内容质量；可重试错误有限退避，权限/参数错误不盲重试，外部写入重试前查幂等和结果。
- 格式要求提供有帮助的正反例，解析兼容等价格式，再严格校验领域约束。标题编号可归一化；缺字段、危险参数、金额/权限错误不能靠宽容解析放过。
- 条数偏多等偏差是否阻断以 PRD 为准；非关键质量瑕疵单记，不无限重试烧钱。区分首次合规、修复后合规与内容质量。
- 固定流程用代码状态机；动态 Agent 定义工具白名单、参数 schema、数据范围、总预算、步数、时限和持久确认点。工具返回和检索内容不能改变这些权限。

## 验收界面

只需临时看一次生成结果的新建后端，可挂载单 HTML + 原生 fetch。已有前端则在原项目加入口；多轮对话、确认、编辑本身是能力时，用正式技术做最小切片继续复用。

仅覆盖当前任务的输入、过程、确认、结果预览/下载和错误恢复。不要在效果待验证时搭与核心无关的完整后台。
