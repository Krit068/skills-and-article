# 部署与运行

## 入口与适配

区分全新云账号、有账号但无资源、已有线上应用；只补当前缺项。先确认本地核心链路与前端证据，识别代码版本、数据、现有云资源、域名、运行时及权限。已有合理平台继续用；无既定平台时可推荐原手册的火山引擎 veFaaS + 网关 + TOS 路线，并核对适用性。

若环境有可用 veFaaS 技能，部署操作前读取其中当前文档；没有时查官方文档与已安装 CLI help，不要求为了本技能完整而预装工具。原手册 CLI 0.2.7、native-python3.12、RDS 企业资格、网关类型、备案/域名条件、TOS endpoint 均是历史线索，不是当前保证。

用产品语言给上线方案摘要：谁可访问/如何登录；数据与文件放哪里；需开哪些服务及费用依据；预计恢复损失窗口；入口地址策略；用户必须亲自完成的步骤。价格、账号资格、地域与政策核对当前来源，未知不估装确定数字。

资源创建、收费扩容、外部发布遵循用户已授权范围。需要新增决定时，先完成代码、构建与方案，使用户能批准具体动作；常规已授权更新不重复问。身份验证或权限授予给出依据真实界面的操作步骤，不猜控制台按钮。

## 发布前完成的工程条件

1. **身份与隔离**：有私人用户数据的线上应用，在开放访问前就实现登录及服务端归属校验，覆盖 API、任务流、产物下载和对象存储。公开无私有数据的产品可无需登录，需在方案中说明。邀请码是可选小范围试用方案；明确邀请码到独立用户的映射，不能让共享邀请码造成串号。拒绝无凭证、错误凭证与越权访问。
2. **持久化**：业务真源应在满足可靠性要求的持久数据库/平台；大文件走对象存储，元数据存归属和对象键。不能把预留实例当磁盘持久化保证，也不能把备份当零丢失保证。
3. **配置**：按项目代码实际读取项列公开构建变量、运行时配置和 Secret。ENV=prod、DATABASE_URL、INVITE_CODES 等不是框架通用开关；值必须与代码匹配。首次服务启动前使必要运行配置可用；若平台须先创建应用才能配变量，先创建未开放的资源，配好再发布。
4. **打包**：检查实际打包规则并查看产物清单，排除 .env、密钥文件、虚拟环境、数据/备份、缓存和本地部署凭据。不能仅看到 ignore 文件就断言生效；Next standalone 只含追踪所需运行依赖，不上传整个开发 node_modules。
5. **可观察与回退**：请求/任务 trace ID、结构化元日志、必要告警；不上传密钥、完整用户文件或私密 Prompt。保存旧版本/配置、数据库变更和回退步骤，回滚代码前检查旧版兼容新数据。

## 若确需 SQLite 临时实例方案

它是有明确损失窗口的受限过渡方案，不是通用生产默认。只有用户可接受最近备份之后的数据损失，且能保证单一写入者和恢复流程时才采用；否则推荐可靠的外部数据服务并说明成本。

- 实例 /tmp 可被回收、替换或重建；最小实例数为 1 仍可能有扩容或滚动期间多个实例，不能保证同一实例常驻。要处理单写者、发布切换和备份覆盖竞态，无法保证就不用本地数据库做真源。
- 为备份定义最大可丢数据时长（RPO）和恢复时长（RTO）。使用一致性快照/SQLite Online Backup API，不能简单复制正写入的数据库并忽略 WAL；备份对象版本化、校验完整性且有保留策略。
- 恢复前验证 schema/完整性，在新实例隔离演练恢复，再开放写入；不能每次启动无条件用旧快照覆盖新数据。记录最后成功备份与失败告警。
- 迁移 PostgreSQL 需验证 SQL/字段/事务差异、导入数据与回退，不假定换连接字符串就完成。

SQLite 备份方法依据：[官方 Online Backup API](https://www.sqlite.org/backup.html)。预留实例官方定位是预热和降低冷启动延迟，不能据此推导磁盘耐久性：[火山引擎预留实例](https://www.volcengine.com/docs/6662/1257650)。

## veFaaS 执行顺序

以下是操作意图，实际子命令及参数先核对当前工具，不直接复制历史手册整段命令：

1. 检查 CLI、当前账号、地域、权限和项目绑定；复用已有登录，秘密走受控配置，不把 AK/SK 写在命令参数或聊天里。权限按实际服务和动作最小化，不默认给六类服务 FullAccess。
2. 检测框架，并从项目入口确认构建、启动、端口和可写路径。FastAPI 入口确为 app.main:app 时可用 `python -m uvicorn app.main:app --host 0.0.0.0 --port 8000`；端口匹配平台，依赖已安装。
3. 查可用网关/路由，验证地域、HTTPS、访问方式和超时适配。缺资源才创建；不把资源操作失败一律解释为需要新建。
4. 准备应用并设置启动配置/Secret，验证键名或脱敏状态；不清空原环境，也不盲用 replace 导入覆盖用户配置。
5. 构建并检查产物，发布目标应用，保存版本/发布记录及预期域名。首次实例预留配置如要求先有已发布版本，则部署后单独设置；只有延迟需求及预算授权才开预留。
6. 请求响应不确定或发布仍在 rolling 时先查询操作状态和目标版本，避免反复创建/部署。排查日志、配置和配额；仅在明确识别本次发布、理解影响且有授权时中止发布，再作有限重试。
7. 完成下述线上验收。发布命令成功只是证据之一；命令失败但网页能开也可能是旧版仍在服务，必须核对版本和真实行为。

## Next.js 前端部署

独立 Next.js 与 Python 后端时，可分成两应用；已有一体部署或不同终端不强拆。前端统一代理普通 API 与流式路由，保持鉴权、路径和超时一致。

采用 standalone 时，检查 `output: "standalone"`、实际产物入口、追踪范围；monorepo 入口可能嵌套。standalone 默认不含 public 和 .next/static，若未由 CDN 提供，补到实际运行产物。运行使用对应 server.js，设置平台要求的 PORT 与 HOSTNAME。依据：[Next.js output 文档](https://nextjs.org/docs/app/api-reference/config/next-config-js/output)。

区分构建时内联/生成的配置与运行时读取的配置。rewrites 若使用环境变量生成静态目标，必须让实际构建进程获取该值；远端构建不能假定本地 shell 环境会自动传入。检查构建产物及真实代理目标。需要运行时可变路由时采用明确支持的服务端代理实现，并验证流转发。

## 线上验收与排错

验证 HTTPS 入口及新版本标识、静态样式/字体、真实登录/隔离、普通与流式 API、完整模型任务、私有文件权限、持久化恢复与日志。涉及设备能力做目标真机检查。用户刷新/跨设备数据一致不代替实例重建恢复测试。

| 现象 | 先检查 | 修复方向 |
| --- | --- | --- |
| uvicorn not found / 框架误判 | 入口、依赖和 PATH | 确认模块启动命令，不盲改结构 |
| Read-only / Permission denied | 实际写入路径与运行配置 | 改受支持可写路径；同时解决持久存储 |
| 样式/字体 404 | 产物静态资源及路由 | 补 standalone 静态内容或修 CDN |
| 普通 API 可用但流卡住 | 流路由、鉴权、缓存和超时 | 在公网链路验证分段到达 |
| AccessDenied | 当前身份、地域、失败 action | 补最小所需权限，不全开或反复新建 |
| TOS 签名/路径错误 | 当前地域 endpoint、签名、寻址模式 | 依据官方 TOS/S3 兼容文档适配，不硬用北京地址 |
| 页面可打开但发布异常 | 版本、发布记录和错误日志 | 区分旧版本仍服务与新版已上线 |
| 重建后记录丢失 | 临时存储、备份、写者与恢复 | 修复持久化架构并演练，不仅增加最小实例数 |

更新项目运行文档中的实际入口、登录方式（不含秘密）、配置键、版本、恢复/回滚步骤和已知限制。上线迭代保持原应用、域名和有效配置，只改本次必需项。
