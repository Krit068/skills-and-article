## 合并、修正与适用条件

| 原文问题或容易误读之处 | 技能处理 | 依据/性质 |
| --- | --- | --- |
| 流程图反复写确认，但通用第六节及前端第 23 节允许无关键问题继续 | 常规报告后执行，已有授权不重问，重大未授权决定才确认 | 原文内部统一；保留用户范围 |
| Python/Node/Next/React 等固定参考版本 | 保留技术偏好，实际查当前维护与兼容版本并锁定 | 原文版本策略 |
| “只能当前阶段”可能导致全流程任务频繁停止 | 保持逐阶段证据门槛，已授权全流程在证据通过后继续 | 范围澄清 |
| 前端所有状态被理解成后端必须完整实现 | 区分客户端连接状态与业务生命周期，按需求裁剪 | 两份手册状态原则合并 |
| 内容条数偏差一概不算错误 | 由 PRD 区分硬契约与质量容忍度，严格关键校验 | 避免把示例泛化 |
| 音频浏览器格式写死，语音对练不展示评分写成通用要求 | 运行时探测；会中信息以当前 PRD 为准 | 原手册能力探测原则与场景边界 |
| AK/SK 交给 AI、FullAccess 六项默认全开 | 受控凭据录入、最小服务/action 权限，配置不回显 | 秘密保护与按需模块原则一致化 |
| 最小实例数被描述为数据不丢关键 | 预留用于预热，不能推导临时磁盘耐久；独立验证恢复 | 官方定位 + 工程推论 |
| 周期上传 SQLite 数据文件被当通用持久化 | 受限单写者过渡方案；一致快照、版本化备份、RPO/RTO、恢复演练 | SQLite 官方备份方法 + 故障边界补充 |
| 前文“先部署再设预留”与后文首次带 minInstance 矛盾 | 当前工具核验；若要求初始版本，则首次发布后独立设预留 | 原手册 V1.1 修正优先，命令不永久固化 |
| “网页能打开”是上线唯一判据 | 同时核对新版本、关键链路、权限、文件和恢复 | 防旧版本仍在线造成误判 |
| 登录、文件/数据保护放在上线后 | 含私有数据的应用在开放访问前就绪并验证 | 原文强制底线与实施顺序统一 |
| ENV=prod、DATABASE_URL 是通用开关 | 按实际项目读取配置；资源存在后、首次启动前注入 | 避免项目示例变框架事实 |
| shell 注入构建变量即认定远端 build 收到 | 核对实际构建环境和产物代理目标 | 部署方式差异补充 |
| RDS 仅企业、免备案、网关默认、运行时及 endpoint | 实际部署时查当前账号、地域和官方规则，不固化结论 | 时效信息待现场核验 |
| 改 DATABASE_URL 就完成数据库迁移 | 增加类型/SQL/数据导入/兼容和回退验证 | 原手册迁移底线补足 |

## 外部核对来源

不提供批量部署/开户/密钥处理脚本：平台契约与账号绑定变化大，固定脚本会掩盖需要现场验证的条件。本技能在实际任务中使用当前可用工具和文档。
