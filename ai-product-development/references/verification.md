# 验收与交接

## 判断依据

以 PRD 与当前阶段验收标准为准，不虚构准确率、响应时延或成本门槛。证据状态统一为：通过、失败、待验证、不适用；不适用说明理由，未执行不能算通过。使用 [验收交接模板](../assets/acceptance-handoff.md)。

测试按变化范围与风险选择；已有可靠检查优先复用。新建核心能力覆盖必要逻辑与失败路径，不为简单样式修改编写重复实现的测试，不为“覆盖数量”重复付费调用。

## 两类模型证据

| 层 | 验证对象 | 必留证据 |
| --- | --- | --- |
| 离线 mock 自动化 | 业务逻辑、合法/非法状态转换、幂等、参数校验、解析器、统一错误与可重试分类 | 实际命令、结果、失败原因与覆盖范围 |
| 真实模型端到端冒烟 | 真实输入 → 模型 → 校验/持久化 → 用户可查看结果 | 日期、代码/Prompt 版本、实际模型、样本标识、输出位置、耗时、用量/成本及质量判断 |

每种不同模型调用契约、每条关键用户链路至少有代表性真实路径，复用同一服务的接口记录覆盖关系。纯工程改动未影响模型契约时，不必机械重复真实调用。

无真实 Key 不阻塞实现或离线测试，但第二层保持待验证。需要额外付费且缺授权时先准备输入、预算和验证步骤；实际调用遵循已有授权。不要索要密钥明文进入聊天。

确认认证/SDK 初始化错误、真实网络时延和输出质量；危险故障可在可控测试中注入，不为测试故意消耗生产限额。记录首次格式合规、重试后合规与内容/数量约束偏差，质量容忍度由 PRD 或用户判断。

SSE 可用 `curl -N` 或等价流客户端计时，检查首事件、持续分段、正常终止与失败结构；认证信息不出现在日志或报告。浏览器经真实代理再验证一次，后端直连流通畅不等于公网链路通畅。

## 恢复与权限证据

- 创建长任务、保存中间结果或等待确认后刷新；按原 ID 恢复，不重新创建。
- 可控环境重启服务，检查重要数据、确认点与未完成任务的恢复或明确终止策略。
- 重复点击、提交超时、请求重试不会重复副作用；取消请求与取消任务的行为符合文案。
- 多用户产品使用两个测试身份验证列表、详情、修改、任务流和文件归属；不只验证前端隐藏按钮。
- 文件上传验证尺寸、真实类型、安全文件名与路径边界；不将生产用户数据当测试材料。

## 前端证据

执行项目适用的 lint、类型检查、相关测试和生产构建；记录未解释错误，不通过禁用检查获得通过。真实浏览器检查 Console/Network、代表页与核心流程、加载/空/错/等待确认、媒体和恢复。

检查目标桌面与移动宽度；语音等设备能力用真机。缺浏览器/设备时列具体待验证步骤，不能把截图或构建称为完整交互验收。

## 上线证据

核对目标代码/构建版本，访问 HTTPS，验证身份隔离、关键用户任务、普通/流式代理、文件读写、持久化/恢复、必要日志/告警。恢复演练优先测试环境或隔离副本，不为了验收破坏生产数据。

备份必须有实际一致性快照、校验和恢复证据；“备份文件存在”“网页能打开”“最小实例为 1”均不能单独证明上线可靠。

## 交接给产品经理

每项清单写“打开哪个已验证地址 → 输入什么非敏感样本 → 点哪个操作 → 应看到什么 → 失败后反馈什么”。没有实际地址写未生成，不造演示 URL。业务质量需用户判断时标记尚待人工验收，AI 不代签。

收尾给可运行成果、重要检查结果、未完成项及原因、当前限制与下一步；更新启动/配置说明。停止不再需要的临时服务；用户需要预览时保留并说明地址和用途，不关闭用户原有进程。

按授权范围继续后续阶段或完成交付；仅有测试通过不能扩大部署、收费资源或外部发送权限。
